>_ 编码格式与兼容说明

01 / 为什么要有协议头？

国际摩斯码本身仅定义有限的字母、数字和标点，不定义中文、Emoji 和大小写。要无损还原任意文本，就必须约定一种可逆格式。新版 UTF-8 HEX 不再使用需要专门学习的字节控制串，而是采用通用 UTF-8 + 十六进制（HEX）。

02 / 无附加提示词的自描述编码

原文按 Unicode 码点分别转换为 UTF-8 字节，每个字节写成两个大写十六进制字符，码点之间用空格分组。例如：MORSE UTF8 HEX E4BDA0 E5A5BD（表示“你好”）。然后使用标准国际摩斯映射，字符之间加空格，单词之间加 /。标准摩斯解码器可以读取对应的 ASCII 中间串，再将 HEX 字节拼接并按 UTF-8 还原。复制按钮只复制摩斯码，不附带任何解码提示词。

03 / 0 和 1 模式

经典模式以 . 表示点、- 表示划；二进制显示模式以 0 表示点、1 表示划。其他字符分隔空格、词间 / 完全相同。0/1 是摩斯符号的可逆替换，不是字符的 ASCII/Unicode 二进制编码。解码器能自动识别两种点划写法，但混合使用会报错。

04 / 兼容边界与旧版数据

可以直接粘贴外部普通摩斯进行解码，例如 .... . .-.. .-.. --- / .-- --- .-. .-.. -..。对于可无损使用标准摩斯表示的全大写英文、数字、常见标点和单个词间空格，直接输出普通国际摩斯，不添加头部。其他文本使用 MORSE UTF8 HEX ... 自描述格式。普通网站只会还原成这一中间字符串，不会自动还原 Unicode。历史 MSM1 和 MSM2 UTF8 HEX 数据仍能在本工具解码；已识别的损坏头部会报错。

05 / 无损边界

不执行大小写规范化、Unicode 归一化或换行转换。内部保留 CRLF、LF、CR，Emoji 组合序列与组合音标。浏览器文本框可把 CRLF 显示为 LF，复制时仍使用内部原文；在编辑已存在 CRLF 的文本时保留未修改的换行。孤立 UTF-16 代理项不是有效 Unicode，会明确报错。

01 / WHY IS A WRAPPER NECESSARY?

International Morse code defines a limited set of letters, digits, and punctuation. It does not define Chinese characters, emoji, or letter case. A reversible container is therefore necessary for lossless Unicode. UTF-8 HEX uses familiar UTF-8 and hexadecimal instead of proprietary data escapes.

02 / SELF-DESCRIBING INTERMEDIATE FORMAT

Each Unicode code point becomes UTF-8 bytes represented by uppercase hexadecimal digits, with spaces between code points. For example: MORSE UTF8 HEX E4BDA0 E5A5BD. Every intermediate character is mapped to standard Morse, separated by spaces, with / separating words. Other Morse decoders can recover this ASCII intermediate; the HEX bytes must then be decoded as UTF-8. Copying the Morse output includes only Morse symbols, spaces, and word separators.

03 / DOT-DASH AND 0/1

Classic format uses . for dot and - for dash. Binary display format uses 0 for dot and 1 for dash. Spaces and word separators remain the same. Binary here is a substitution of Morse signals, not the binary representation of Unicode or ASCII. The decoder automatically accepts either notation, but rejects mixed notation.

04 / COMPATIBILITY

You can decode external standard Morse such as .... . .-.. .-.. --- / .-- --- .-. .-.. -... Fully uppercase ASCII with digits, common punctuation, and single inter-word spaces uses native international Morse directly without any wrapper. Unicode, lowercase letters, and exact whitespace use the MORSE UTF8 HEX ... intermediate. Ordinary third-party Morse readers can recover that intermediate ASCII text, but cannot automatically restore Unicode. Legacy MSM1 and MSM2 UTF8 HEX packets remain supported. Malformed detected packets produce explicit errors.

05 / LOSSLESS LIMITS

Unicode normalization, case conversion, and newline normalization are not applied to the underlying data. CRLF, LF, CR, joined emoji, and combining marks are preserved. Browsers display CRLF as LF in a textarea, but clipboard output uses retained raw text. Isolated UTF-16 surrogate code units are not valid Unicode and are rejected explicitly.
